# mosila console 0.3.4 正式版

作者：ChatGPT、酸菜鱼。

免费开源，项目代码使用 MIT 许可证（见 `LICENSE`）。支持 MOSILA 与魔灯客九号 N/F/M 大灯 3.0；其他魔灯客产品暂未适配。

基于 MOSILA v1.0.6 蓝牙指令分析独立重写的 Android 应用，使用 Java 与 Android 原生界面。并非原 APK 的完整源码恢复，也不是灯具厂商官方应用。

## 下载

当前正式版与源码在 [`releases/`](releases/) 目录中，包含 SHA256 校验值。此目录中的 `MOSILA-v0.3.4.apk` 保持既有签名，适合覆盖更新。正式发布后也可从 GitHub Releases 下载同签名 APK。

## 安装使用

1. 安装 `MOSILA-v0.3.4.apk`。可直接覆盖 0.3.4-test / 0.3.3 / 0.3.2 / 0.3.1 / 0.3.0 / 0.2.0 及 0.1.0 / 0.1.1 / 0.1.2 / 0.1.3 / 0.1.4 / 0.1.5 / 0.1.6 / 0.1.7 / 0.1.8 / 0.1.9 / 0.1.10 测试版，包名和签名保持一致。桌面名称为“mosila console”，包名为 `com.suancaiyu.mosilalight`，可以与原版共存。
2. 打开大灯电源，先断开原应用对大灯的连接。
3. 进入“设备”，允许“附近的设备”权限，点击扫描，选中你的大灯并连接。
4. 连接完成后再进入“调色”“灯效”或“设置”。有该设备参数记录时会自动恢复；无记录的新设备不自动下发。
5. 本版首次更新后先手动连接成功一次。以后重新打开应用，会扫描 15 秒，按地址找到上次连接的大灯后自动重连。蓝牙未开启或权限未授予时按系统提示处理。
6. 设备页可重新查找或清除连接记忆；参数记录与重连记忆分别保存，清除重连记忆不会删除设备参数。
7. 多台连接时，可在设备卡片上选择本次需要控制的设备。

没有账号、卡密或广告，没有网络权限。Android 8.0 及以上可安装；本次没有连接真实大灯，不保证每种硬件版本都支持。

## 功能

- 深色界面，色盘 / HEX 输入 / 颜色预设，RGB 与氛围灯强度调节。
- 根据提供的实物照片绘制一体式三透镜灯具、顶部连续灯带和两侧层叠灯条，不绘制固定耳、螺丝或孔位。
- 恢复最初的深蓝底青柠电源图标，品牌名为“mosila console”。
- 灯光开关与 A/B 路控制。
- 原应用 213 种中文灯效、中文名称包含搜索 / 编号搜索、速度与灯效 A/B 选择。
- 灯效弹窗统一深色圆角材质；滚轮停止时应用中心灯效，点击条目也立即应用，保持弹窗打开。搜索和打开菜单不会自动发送，未连接时，有明确设备档案则进入草稿，确认后保存到该设备；没有设备档案时仅保存通用预览。
- 刹车常亮 / 爆闪、转向流水 / 频闪设置。
- 开机模式 0–6、点数 10–100、使用当前选定颜色。
- 光高方向 0/1 长按调节，每 125 ms 发送；松手、切页、退到后台均停止。
- 光高数值 0–18、自检与 6 种 RGB 线序。
- 蓝牙扫描、服务检查、多设备选择、连接超时、写入队列与可复制通信记录。

## 已知边界

- 协议来源是静态分析；已知的包格式不等于硬件实测通过。
- 光高方向 0/1 与实物运动方向仍需短按确认。
- 刹车、转向按钮配置相应效果，不模拟车辆输入。
- 本地颜色、模式与选择值不是设备回读。无响应写入也没有设备执行确认。
- 开机命令最后一个参数保留原默认值 255；具体含义未验证。
- 本版未实现原应用的全部分组、音乐、启动定时等功能，也未复用卡密、网络或营销模块。
- Android 11 及以下扫描需要定位权限及系统定位服务；Android 12 及以上使用附近设备权限。
- 本应用不在后台持续扫描或调节光高。

## 0.1.1 调色修正

0.1.0 把调色包最后一个参数初始化为 0，并用“白色通道”标注。重新核对原版 AOT：主页构造器在 `0x54dbc0` 初始化该字段为 255（`field_23`），`didSelectColor` 把它作为 `CmdRgb.field_27` 写入 payload 最后一个字节。这是首版独立实现中的明确差异，与用户报告的调色后熄灭现象吻合。

本版恢复默认值 255，旧键 `white=0` 自动迁移为 `colorIntensity=255`，已有合法非零值保留。首次启动也使用 255。强度滑条范围改为 1–255，避免调整颜色或强度时发送零值；关闭灯光使用单独的开关按钮。默认红色报文现在为 `69 96 05 02 FF 00 00 FF`。

这个字段按输出强度提供操作入口，但目前还没有真实设备抓包或固件证明其物理通道定义。恢复原版默认值后的硬件效果仍需复测。0.1.1 当时不会自动向大灯写入指令；0.1.7 起按各设备已有记录恢复。首次建立记录时请连接后重新设置。

恢复初始电源矢量图标。灯效选择改为深色居中滚轮，滚动停止或点击即可发送，无需关闭菜单或再按应用。中文搜索按名称任意位置匹配，过滤结果保留原始协议索引，避免搜索后发送错误灯效。支持全角数字输入，空结果不发送；进入后台时关闭选择器。

桌面名称、页眉和设置页名称统一为小写 `mosila console`。保持包名和测试签名，支持覆盖安装。

## 0.1.5 连接记忆

仅在连接完成并通过大灯服务 / 写特征校验后保存蓝牙地址和名称；失败尝试不会覆盖记忆。下次创建应用页面时自动扫描附近设备，仅连接地址完全一致的设备，不按同名猜测。15 秒内找不到则停止并记录提示，提供手动重试入口。手动停止、清除记忆或进入后台会取消自动扫描；同一页面从后台恢复不会反复扫描。首次没有记忆时仍手动选择设备。使用设备端随机变化的蓝牙地址时需重新选择。

0.1.5 的连接过程不发送灯光控制包；0.1.7 起会恢复已有设备参数。记忆保存在应用私有数据中，卸载或清除应用数据会删除记忆。

## 0.1.6 状态回读探测版

此版用于验证大灯是否提供状态回读通道，尚未实现自动匹配实物灯效。

连接后在“设备”的已连接设备卡片中点击“检测状态回读（实验）”，等待完成，再点击“连接记录 → 复制”。记录包含特征属性、读取返回值和通知数据；返回数据未经含义确认，不修改当前灯效。探测期间请暂缓控制灯光。每项操作超过 5 秒未响应会关闭连接，之后可手动重连；不会清除连接记忆。

仅读取大灯 EEA0 服务中支持 READ 的特征，并对支持 NOTIFY / INDICATE 的特征写入标准 CCCD 订阅值。没有发送猜测的私有查询包，也没有向灯光控制特征写入命令。日志按设备标识区分，最多保留 160 条。分析依据和现场步骤见 `design/STATE_READBACK.md`。

## 0.1.7 按设备自动保存与慢速恢复

所有已设置参数按蓝牙地址分别保存，不按设备名称混用：灯光开关、纯色 RGB / 强度、灯效编号 / 速度 / 灯效 A/B、开机模式 / 点数 / 独立 RGB、刹车效果、转向效果、自检、总 A/B 路开关、RGB 线序及光高数值。所有进入发送队列的设置都会立即自动保存；开机模式和点数修改也改为直接自动保存 / 发送。长按升降只记录最后操作方向，不在重连时重放移动动作。

连接通过服务检查后，等待 700 ms，再将该设备记录编排成恢复队列。每包等待 Android 写入回调，回调后至少间隔 400 ms 才发下一包；普通控制命令也串行，并有 150 ms 间隔。先恢复配置，再恢复最后使用的纯色或灯效（另一组仍保存在本地），最后恢复 A/B 路及关闭状态。每个地址只恢复自己的记录，未设置过的项目不猜测默认值并覆盖实物。

恢复期间的新操作先自动保存，排在该设备的恢复队列后发送；高频颜色和同类设置合并为最新待发送值。写入被系统拒绝或回调报错会停止本次队列，超时则断开连接；保留参数供后续重连恢复，不盲目重发。日志中“已提交”指 Android 写入流程完成，不是大灯固件确认执行。

设备页可“单独设置此设备”，此时只选中该台设备并加载它自己的参数到界面；多选时当前操作分别保存到各台所选设备，其他已保存项目保持各自的值。新设备不会继承另一台设备的配置。旧版全局缓存没有可靠的设备归属，不自动分配给地址；更新后请连接各设备设置一次。0.1.7 的无连接选择仅保存通用预览；0.1.8 已增加明确设备档案的离线编辑，仍不会把预览擅自绑定给附近陌生设备。

参数不需要额外的“保存”操作，卸载或清除应用数据会删除。完整字段、恢复顺序和边界见 `design/DEVICE_PROFILES.md`。

## 0.1.8 离线保存与队列跟进

修复断线后修改只保存到通用缓存的问题：断线后继续修改当前设备参数，会保存到该设备的地址档案；下次连接按新值恢复。设备页列出所有已保存设备，可选“离线编辑已保存参数”。离线选择会取消其他设备的控制勾选，避免修改误发到仍连接的另一台大灯；界面明确显示正在离线编辑。应用重启保留当前编辑档案，自动重连目标仍取最近成功连接的设备。

离线保存的反馈与实际入队发送分开，不再把离线灯效选择显示成“已发送”。没有明确档案时仍不绑定设备。设备名称单独记录到档案，空档案不会产生默认恢复指令，兼容0.1.7已有参数。单个损坏字段被独立跳过，不影响其他有效设置。

所有持久设置的待发项按字段合并为最新值，包括A/B路开关和线序；长按即时动作保留原有停止规则。恢复队列仍按快照逐包发送，普通待发项合并不会改变400ms恢复间隔。

## 0.1.9 离线确认、取消与编辑状态

离线编辑改为草稿会话。点击“离线编辑”后，顶部显示“编辑中”、当前设备名称和地址，固定提供“确认”“取消”，切换调色 / 灯效 / 设置页时保留。已修改字段数量显示在顶部。修改只暂存在内存草稿，不写入设备参数记录；“确认”将本次修改一次合并保存到对应地址，重连后恢复；“取消”或返回键丢弃所有未确认修改，恢复原记录。

0.1.9 曾在断线调整时自动进入草稿；0.1.10 按用户要求移除此入口，必须点击离线编辑。在线操作仍自动保存，不要求确认。离线草稿不会进入蓝牙发送队列；编辑期间自动重连只恢复之前已确认的记录，不会覆盖草稿或下发未确认内容。编辑结束前不能切换控制目标。确认会返回设备页，保存提示明确为重连后恢复。

退到后台不会自动确认；同一页面恢复时草稿还在，进程销毁后未确认草稿不保留。旧版设备记录与400ms恢复节流保持兼容。

## 0.1.10 修复编辑入口与扫描名称

只有点击设备页“离线编辑已保存参数”才进入编辑中。打开应用、加载已保存设备、未连接时点颜色或灯效，都不会自动打开草稿，也不会修改设备参数记录。未连接时的操作仅用于通用预览，需要保存设备参数时先点击明确的离线编辑入口。

扫描名称增加完整 / 缩短广播名的原始AD字段解析、UTF-8中文名、每次扫描结果刷新系统缓存名称、批量扫描回调，以及已保存名称兜底。先收到无名称广播、后续才获得系统名称时，列表也会更新；完整广播名不会被后续短名称或空包覆盖。扫描名称缓存独立于灯光参数，不会给陌生设备创建参数档案。确实没有广播名称、系统名称或历史名称的设备显示地址尾号，便于区分；这不代表已经确认其真实设备名称。

## 0.3.3 首次使用引导与免费开源提示

全新安装第一次打开，先选择mosila或魔灯客，不预先默认确认任何品牌。引导共三步：选品牌、了解蓝牙连接、了解自动保存/离线编辑/删除参数。最后点击“进入设备页，开始使用”完成引导，之后在设备页手动扫描连接。魔灯客卡片明确当前仅支持九号N/F/M大灯3.0。

完成前隐藏控制导航和连接入口，不扫描、不请求蓝牙权限、不发送控制指令。上一步和系统返回可返回前一页；退出/进程重启会恢复未完成的步骤和暂选品牌。只有完成最后一步才正式保存品牌和完成标记，之后启动直接进入控制台，仍可从console切换品牌。

已有安装覆盖更新，按原有品牌/页签/参数/连接记忆识别为已使用用户，自动跳过本次新手引导，保留当前配置。首次引导只对全新安装且没有已有配置的用户出现。

进入控制台后弹出“免费开源说明”，文案为“此软件免费开源，如果你是通过付费获取的恭喜你被骗了”。提供“不再提醒”复选框与“我知道了”按钮；勾选立即保存，之后启动不再弹。未勾选时每次冷启动提醒一次，旋转屏幕/切换品牌不会重复弹出。新用户在完成引导后才显示；老用户升级进入控制台时也会显示。提示关闭前暂缓自动查找上次设备，关闭后继续原本的自动重连逻辑。

两个品牌设置页最底部均有“关于软件”。其中显示应用名、实际版本号、免费开源文案与支持的灯具，并提供“查看使用引导”入口；这里是只读帮助，不会清除已有品牌选择或参数。

## 0.3.2 手动删除设备参数

两个品牌的设备页均添加“删除已保存参数”，已连接、已扫描未连接以及不在附近的已保存设备均可操作。弹窗显示品牌、设备名和MAC，取消不删除，确认只删除所选品牌下该地址的灯光参数。

连接记忆保留；如果也不想自动查找该设备，可再使用已有的“清除连接记忆”。删除不会向灯具发送恢复出厂指令。后续重连不再恢复已删除参数；再次调节会重新按设备自动保存。

如果该设备仍在恢复或有待发指令，确认删除时断开这台设备并取消其剩余队列，已进入蓝牙发送过程的单条报文无法撤回。没有待发指令时保留连接。其他设备与其他品牌的记录不受影响。正在离线编辑时需先确认或取消草稿，才能删除参数。

## 0.3.1 品牌蓝牙隔离修复

修复MOSILA已记忆设备在魔灯客扫描列表出现的问题。两品牌的连接记忆和参数原已分开，但扫描曾接收所有设备，名称缓存与会话日志仍共享。现按设备历史归属、广播名称、广播服务排除已知另一品牌的设备；名称缓存、扫描会话和日志也分品牌处理。

切换品牌后，旧扫描结果、批量结果和失败回调不能再影响新品牌；旧列表里的设备对象不能再次发起连接。权限/蓝牙开启请求也不会继承原品牌的待扫描意图。无法识别归属的新设备保留扫描可见性，避免无名称设备被直接隐藏，最终仍需对应服务及产品58核对才能控制。

可以覆盖安装，不必卸载或清除数据。保留既有设备参数和连接记忆；旧版共享名称缓存不再读取，已连接设备名可从各品牌已保存记录恢复，其他名称从实际广播重新获取。

## 0.3.0 九号 N/F/M 大灯 3.0

点击左上角console → 魔灯客，仅支持原版大灯产品ID58（JHDD30）。三路为一字日行灯/侧翼灯/恶魔眼，灯珠数量45/56/45，线路号1/3/4。支持独立调色、三路同步、每路10种灯效、1–7色、亮度、速度档位、方向、宽度、单色闪烁，以及开机颜色/效果/颜色自检、电调自检/效果/位置。

先断开原版应用，再到设备页扫描连接。程序先订阅通知并发原版A9查询，仅产品ID58通过后才开放控制。错误型号、无回复或MTU不足不会下发灯光参数。首次没有保存记录时不发送默认设置；连接后调整过的参数按MAC自动保存，重连后每条等待回调且间隔至少500ms恢复。

不同品牌和不同设备分开保存。未连接时调整只预览，必须明确点设备页的离线编辑才能保存草稿；顶部有编辑中、确认和取消。灯效二级菜单支持中文搜索、滚动停下即选择。桌面名仍是mosila console，初始版图标保留。

实物尚待验证。请依次测试三路颜色/开关、动态效果、重连恢复，再测试电调；如果连接停在型号核对或控制异常，复制设备页连接记录反馈。当前只读型号和固件版本，不回读当前灯效状态。协议依据及限制见design/MODENGKE_NFM30.md。

## 构建

依赖 JDK 17+、Android SDK Platform 35 与 Android SDK Build Tools。运行时不需要第三方库。

```bash
python3 build.py --android-jar /path/to/android-sdk/platforms/android-35/android.jar \
  --build-tools /path/to/android-sdk/build-tools/35.0.0
```

也可设置 `ANDROID_HOME` 后运行 `python3 build.py`。脚本会编译资源和 Java、执行协议测试、生成 DEX、对齐并签名 APK。请使用 Linux 运行这份独立构建脚本。

项目同时提供 Gradle 配置，可用 Gradle 8.9 / JDK 17 构建 `:app:assembleDebug`；未打包 Gradle 分发文件。交付 APK 使用上述独立脚本生成。

交付的正式 APK 保持既有签名，以便覆盖更新。签名私钥不发布到公开仓库。自行构建时，`build.py` 会在本地生成测试签名；请保留该本地文件以便后续自建版本覆盖安装。自建 APK 与下载的正式 APK 签名不同，不能相互覆盖安装。

## GitHub 自动构建

`.github/workflows/android.yml` 在推送 `main` 或手动运行时执行运行时测试并重新编译 APK，核验仓库中正式 APK 的签名和版本后发布正式 Release。正式 APK 在本地签名，私钥不进入仓库；CI 临时签名的验证包不发布。Release 附带正式 APK、源码 ZIP 与 SHA256 校验值。已有同名 Release 时不重复发布。
独立运行回归测试：安装 Maven、JDK 17 和 Android SDK 35 后运行 `python3 runtime-tests/run.py`，也可通过 `--android-jar` 指定平台文件。脚本准备 AndroidX 的 AAR 类库后执行 Maven 测试。没有实物大灯时，该测试只能验证 Android 模拟运行时行为及协议数据，不能代替硬件验收。

## 文件结构

- `app/src/main/java/.../MainActivity.java`：原生界面与交互。
- `BleController.java`：BLE 连接、每设备恢复及节流发送队列。
- `DeviceProfiles.java`：按蓝牙地址隔离的参数记录、验证及恢复编排。
- `Protocol.java`：纯 Java 指令编码。
- `app/src/main/assets/modes.json`：从原应用中文本地化列表整理的 213 个模式名，模式列表索引作为 `03` 指令的子模式值，普通模式字段为 0。
- `tests/ProtocolTest.java`：报文样本与参数边界检查。
- `runtime-tests/`：Robolectric Android 运行时测试；其 SDK 本地路径需按环境修改，测试的 Maven 依赖不属于应用运行时依赖。

协议 UUID：服务 `0000eea0-0000-1000-8000-00805f9b34fb`，写特征 `0000ee01-0000-1000-8000-00805f9b34fb`，使用 without-response 写入。普通命令为 `69 96 LEN CMD ...`，线序为原始 `91 index`。
